`ROADMAP.md` §1 の診断を回す。詰まりの原因を「知識不足 / 考察不足 / 実装力不足 /
速度不足」に分け、どこに偏っているかで翌週の練習を変える。

## 手順

1. `log.md` を読む。書式は `日付 / 問題 / 結果 / [分類] / 一行メモ`。

2. 直近 7 日の行を集計する:
   - 問数と、自力AC / 解説AC / 未AC の内訳
   - `[分類]` の内訳
   - 結果に `(擬似)` が付いた行の数（擬似コードから実装した回）
   - メモに出てくる手法の重複（同じもので 2 回以上詰まっていないか）

3. **当該期間の行が 3 行未満なら、何もせずに終わる。** 集計しない、`weekly.md` に
   書かない、commit しない。「今週は記録が N 行なので集計をしていない」と 1 行だけ返す。
   **数字を水増ししたり、記録にないことを推測で補ったりしないこと。**

4. 集計できたら、`ROADMAP.md` §2 の必修リストと照らして、**翌週優先すべき項目を
   1〜2 個だけ**名指しする。多く挙げない。判断の根拠:
   - 知識不足が多い → §2 の未習項目を埋める
   - 考察不足が多い → 考察時間を長く取る、小ケースを手で列挙する練習
   - 実装力不足が多い → 同じ典型を繰り返し実装
   - 速度不足が多い → バチャを週 2 回に増やす
   - **`(擬似)` が期間の半分を超えていたら**、「週 1 回は Mac で 1 から Rust を書く」を
     入れる。考察は本人でも実装を自分で書いていないので、そのままだと実装力が伸びない

5. `weekly.md` の**先頭に**追記する（新しい週が上。無ければ作る）:

   ```
   ## YYYY-MM-DD の週

   取組 N 問（自力AC a / 解説AC b / 未AC c）、うち擬似コード経由 m 問
   詰まり: 知識不足 x / 考察不足 y / 実装力不足 z / 速度不足 w

   翌週の優先: （項目と、なぜそう判断したかを 1〜2 行）
   ```

6. commit して push。コミットメッセージは日本語で 1 行。

7. 結果を短く返す。スマホで読むので長くしない。

コードは書かない。問題の解法も書かない。集計と方針だけ。

# AtCoder 練習環境 (Rust)

## セットアップ済みのもの

| | |
|---|---|
| ツールチェーン | `1.89.0` — AtCoder の 2025/10 新ジャッジと同じ rustc を `rust-toolchain.toml` で固定 |
| クレート | ジャッジに存在するものだけを `Cargo.toml` の `[workspace.dependencies]` にバージョン固定で列挙 |
| overflow-checks | release でも **有効**。ジャッジでは無効なので、ここで panic したら本番では黙って誤答になるバグ |

## 使い方

```sh
bin/new abc428          # コンテスト一式を作り、サンプルを取得
bin/new abc428 d e      # 一部の問題だけ
bin/t   abc428 d        # サンプル全件でローカル判定
bin/t   abc428 d 2      # 2 番のケースだけ
bin/t   abc428 d --tl 3 # 実行時間制限を変える (既定 2 秒)
```

生成物:

```
contests/abc428/
├── Cargo.toml
├── src/bin/{a,b,c,...}.rs   # ここを編集して、中身をそのまま提出する
└── tests/{a,b,c,...}/N.in   # サンプル入力
                    /N.out   # サンプル出力
```

開催中のコンテストは問題ページが非公開でサンプルを取れない。
その場合は `bin/new abc999 --no-fetch a b c d` で枠だけ作り、
`tests/a/1.in` `tests/a/1.out` に手で貼る。

## Rust 固有のハマりどころ

- **`use ac_library::...`** — クレート名は `ac-library-rs` だが、`[lib] name` は `ac_library`。
  0.1.1 時代の `ac_library_rs` は 0.2.0 で通らない。
  例: `use ac_library::{Dsu, ModInt998244353 as Mint, Segtree};`
- **`usize` の引き算** — `a - b` で `b > a` だと panic (release でも本環境は overflow-checks 有効)。
  比較は `if a > b`、差は `a.saturating_sub(b)` か `as i64` に上げてから。
- **オーバーフロー** — `N ≤ 10^5` でも和が `10^18` に届く問題は多い。既定で `i64` を使う。
- **`#[fastout]`** — 大量出力の TLE 対策。ただし**インタラクティブ問題では外す**
  (出力がバッファに溜まってジャッジに届かない)。
- **`HashMap` が遅い** — 標準の hasher は攻撃耐性のぶん重い。`rustc_hash::FxHashMap` に置き換える。
- **深い再帰** — 既定スタックで落ちることがある。DFS は明示スタックにするか、
  `std::thread::Builder::new().stack_size(64 << 20)` で回す。

## 毎日の流れ

Mac で Claude Code を開き、`/remote-control`（略記 `/rc`）を打つ。
出た URL か QR をスマホで開けば、**そのセッションをスマホから操作できる**。
実行はすべて Mac 側で起きるので、ネットワークも `cargo` も `git` もそのまま使える。

移動中はスマホから:

| 打つもの | 何が起きるか |
|---|---|
| `/today` | 今日の問題（精選100問の続き）。問題文と制約つき |
| 「ヒント」 | 段階 1 から。1 段階ずつしか上がらない（`CLAUDE.md`） |
| 擬似コード | Rust にしてサンプル判定まで回す（`PSEUDO.md`） |
| `/log ABC106 B 自力AC メモ` | 記録する。**これで出題が次に進む** |
| `/weekly` | 直近 7 日を集計して翌週の優先項目を出す |

接続を切るには `/remote-control` をもう一度打つ（ローカルのセッションは残る）。
Mac がスリープしても復帰時に自動で繋ぎ直す。毎回自動で繋ぎたければ
`/config` の **Enable Remote Control for all sessions** を入れる。

**Mac が起きていてセッションが生きていることが前提**。ここが唯一の弱点で、
クラウドの routine と違って落ちていたら何もできない。

```sh
bin/pick              # 今日の1問を選ぶ（手元でも実行できる）
bin/pick --n 3        # 3 問出す
bin/pick --random     # 精選100問を使わず、難易度帯からランダムに選ぶ
bin/pick --min 600 --max 1200   # --random のときの帯
bin/pick --refresh    # pool.json と SENKEI100.md を作り直す
```

出題は**「分野別 初中級者が解くべき過去問精選 100 問」を分野順に進む**のが既定
（`SENKEI100.md`、出典は `ROADMAP.md` §3）。

**一度に 3 問出て、そのうち 2 問を `log.md` に書くと次の 3 問に移る。**
日付では動かない。1 問しか書いていない間は同じまとまりのままなので、
目の前の課題が毎日入れ替わらない。書き終わらなかった問題は捨てずに
次のまとまりの先頭に持ち越す。問数としきい値は `--n` と `--refill` で変えられる。

解けなかった日も `未AC` で 1 行書けば進む。**書かないと進まない。**
100 問を終えると、これまでどおり難易度帯からのランダム出題に自動で切り替わる。

`pool.json` には**問題文の冒頭・制約・サンプル入出力が先読みして**入れてある。
おかげで `bin/pick` は AtCoder を開かずに問題文を出せるし、`bin/new abc467 c` は
ネットが無くても足場を作れる。クラウドの routine 用に作った仕組みだが、
スマホから読むときにそのまま効くので残してある。

**`--refresh` は普段は要らない。** AC 済みの判定は `bin/pick` が毎回
kenkoooo.com に問い合わせるので、手元で動かしているかぎり常に最新になる。
`--refresh` が要るのは、精選100問の外の問題を `--random` で掘るときに
問題文も先読みしておきたい場合と、`SENKEI100.md` の進捗表示を作り直したいときだけ。

なお `bin/pick` は `log.md` に書いた問題も除外するので、
ネットに出られない場所でもログさえ書いていれば同じ問題は出ない。

## 移動中に実装する

方針が立っているなら、スマホから擬似コードを送れば Rust になって
`contests/<コンテスト>/src/bin/<記号>.rs` に入り、サンプル判定まで通る。
書き方と、変換する側が守る規則は `PSEUDO.md`。

Mac 上のファイルが直接書き換わるので、戻ってきたら `git pull` は要らない。
提出は自分でやる。

**方針を人に決めてもらったら精進にならない**ので、擬似コードに解法が書かれていないもの
（「どう解くの」「BFS で解いて」）はヒント要求として段階制で扱われる。
擬似コードのロジックは直されない。間に合わない書き方でもそのまま実装されて、
指摘が 1 行付くだけ。

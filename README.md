# AtCoder 練習環境 (C++ / Ruby)

使う言語は **C++ と Ruby**。問題ごとに好きな方で書く。Rust は卒業した
（過去の Rust 解答は `contests/*/src/bin/*.rs` に残してあるだけで、もう更新しない）。

## セットアップ済みのもの

| | |
|---|---|
| C++ | `-std=c++23 -O2`（ジャッジも C++23）。`brew` の `g++-NN` があればそれを、無ければ Apple clang を使う |
| `bits/stdc++.h` | Apple clang に無いので `lib/compat/` に代替を置いて `-I` で通している |
| ACL | `lib/ac-library/`（公式そのまま）。`#include <atcoder/all>` が手元でも通る |
| サニタイザ | ローカルのビルドは `-fsanitize=address,undefined` 付き。符号付き溢れや配列外参照はここで落ちる（ジャッジでは黙って誤答になる） |
| Ruby | `ruby` をそのまま実行。**手元は 2.6、ジャッジは 3.4**。新しい構文（`it`、`Data` など）は手元で動かない |

## 使い方

```sh
bin/prepare             # 精選100問ぶんのサンプルをまとめて作る (pool.json から、ネット不要)
bin/new abc428 d        # D の雛形 (C++) とサンプルを作る
bin/new abc428 d --lang rb       # Ruby の雛形
bin/new abc428 d --lang cpp,rb   # 両方
bin/t   abc428 d        # サンプル全件でローカル判定 (cpp と rb が両方あるときは --lang で選ぶ)
bin/t   abc428 d 2      # 2 番のケースだけ
bin/t   abc428 d --tl 3 # 実行時間制限を変える (既定 2 秒)
bin/r   abc428 d        # 判定せず 1 回実行するだけ
```

生成物:

```
contests/abc428/
├── d.cpp / d.rb          # ここを編集して、中身をそのまま提出する
└── tests/d/N.in, N.out   # サンプル入出力
```

`bin/prepare` はサンプルだけ作って雛形は作らない（言語は解くときに選ぶ）。
既にある解答は書き換えない。何度実行しても安全（`--force` を付けるとサンプルだけ取り直す）。

開催中のコンテストは問題ページが非公開でサンプルを取れない。
その場合は `bin/new abc999 --no-fetch a b c d` で枠だけ作り、
`tests/a/1.in` `tests/a/1.out` に手で貼る。
手で貼る代わりに、**問題ページ全体をコピー (Cmd+A, Cmd+C) して `bin/sample abc999 a`** と打てば、
クリップボードから「入力例 N」「出力例 N」を拾って `tests/a/N.in` `N.out` に書き出す。
コピーは 1 回で済む。

## 言語ごとのハマりどころ

### C++

- **`int` の溢れ** — `N ≤ 10^5` でも和が `10^18` に届く問題は多い。既定で `long long`（`ll`）。
  `1 << 40` のようなリテラルは `1LL << 40`。
- **`vector::size()` は符号なし** — `v.size() - 1` は空配列で巨大値になる。`(int)v.size()` に上げてから引く。
- **`endl` を使わない** — 毎回 flush して遅い。`"\n"` を使う。インタラクティブ問題だけ `endl` か `flush`。
- **`unordered_map` が狙われる** — 衝突させるテストを入れられることがある。迷ったら `map`。
- **`mod` の負数** — `(a % m + m) % m`。

### Ruby

- **遅い** — `N ≥ 2×10^5` あたりから単純な二重ループは通らない。ループの中身を減らすか C++ で書く。
- **入力は `gets` を何度も呼ぶより `STDIN.read` や `$stdin.each_line` でまとめて読む**（大きい入力で効く）。
- **整数は多倍長なので溢れない**（速度は落ちる）。`Integer#/` は切り捨て除算（負数は負の無限大方向）。
- **再帰が浅い** — 深い DFS は `SystemStackError`。明示的なスタックにする。
- **配列の負の添字は末尾から読める** — `a[-1]` はエラーにならず末尾。範囲外の見落としに注意。

## 毎日の流れ

Mac で Claude Code を開き、`/remote-control`（略記 `/rc`）を打つ。
出た URL か QR をスマホで開けば、**そのセッションをスマホから操作できる**。
実行はすべて Mac 側で起きるので、ネットワークも `g++` も `git` もそのまま使える。

移動中はスマホから:

| 打つもの | 何が起きるか |
|---|---|
| `/today` | 今日の問題（精選100問の続き）。問題文と制約つき |
| 「ヒント」 | 段階 1 から。1 段階ずつしか上がらない（`CLAUDE.md`） |
| 擬似コード | C++ か Ruby にしてサンプル判定まで回す（`PSEUDO.md`） |
| `/log ABC106 B 自力AC メモ` | 記録する。**これで出題が次に進む** |
| `/weekly` | 直近 7 日を集計して翌週の優先項目を出す |

接続を切るには `/remote-control` をもう一度打つ（ローカルのセッションは残る）。
Mac がスリープしても復帰時に自動で繋ぎ直す。毎回自動で繋ぎたければ
`/config` の **Enable Remote Control for all sessions** を入れる。

**Mac が起きていてセッションが生きていることが前提**。ここが唯一の弱点で、
クラウドの routine と違って落ちていたら何もできない。

```sh
bin/pick              # 今日の1問を選ぶ（手元でも実行できる）
bin/pick --n 3        # 3 問出す
bin/pick --random     # 精選100問を使わず、難易度帯からランダムに選ぶ
bin/pick --min 600 --max 1200   # --random のときの帯
bin/pick --refresh    # pool.json と SENKEI100.md を作り直す
```

出題は**「分野別 初中級者が解くべき過去問精選 100 問」を分野順に進む**のが既定
（`SENKEI100.md`、出典は `ROADMAP.md` §3）。

**一度に 3 問出て、そのうち 2 問を `log.md` に書くと次の 3 問に移る。**
日付では動かない。1 問しか書いていない間は同じまとまりのままなので、
目の前の課題が毎日入れ替わらない。書き終わらなかった問題は捨てずに
次のまとまりの先頭に持ち越す。問数としきい値は `--n` と `--refill` で変えられる。

解けなかった日も `未AC` で 1 行書けば進む。**書かないと進まない。**
100 問を終えると、これまでどおり難易度帯からのランダム出題に自動で切り替わる。

`pool.json` には**問題文の冒頭・制約・サンプル入出力が先読みして**入れてある。
おかげで `bin/pick` は AtCoder を開かずに問題文を出せるし、`bin/new abc467 c` は
ネットが無くても足場を作れる。

**`pool.json` は git に入れていない**（`.gitignore`）。中身は AtCoder の問題文で、
権利は AtCoder と作問者にあるため、リポジトリに同梱して再配布はしない。
クローンした直後は空なので、`bin/pick --refresh` で作る（全問ぶん取りに行くので 2〜3 分）。

**`--refresh` は普段は要らない。** AC 済みの判定は `bin/pick` が毎回
kenkoooo.com に問い合わせるので、手元で動かしているかぎり常に最新になる。
`--refresh` が要るのは、精選100問の外の問題を `--random` で掘るときに
問題文も先読みしておきたい場合と、`SENKEI100.md` の進捗表示を作り直したいときだけ。

なお `bin/pick` は `log.md` に書いた問題も除外するので、
ネットに出られない場所でもログさえ書いていれば同じ問題は出ない。

## 移動中に実装する

方針が立っているなら、スマホから擬似コードを送れば C++ か Ruby になって
`contests/<コンテスト>/<記号>.cpp`（または `.rb`）に入り、サンプル判定まで通る。
書き方と、変換する側が守る規則は `PSEUDO.md`。

Mac 上のファイルが直接書き換わるので、戻ってきたら `git pull` は要らない。
提出は自分でやる。言語を書かなかったら C++ になる（Ruby にしたいときは「Ruby で」と添える）。

**方針を人に決めてもらったら精進にならない**ので、擬似コードに解法が書かれていないもの
（「どう解くの」「BFS で解いて」）はヒント要求として段階制で扱われる。
擬似コードのロジックは直されない。間に合わない書き方でもそのまま実装されて、
指摘が 1 行付くだけ。

- **問題文・制約・サンプル入出力**は AtCoder（および各作問者）に権利がある。
  このリポジトリには含めていない（`pool.json` は `.gitignore`）。
  `bin/pick` / `bin/new` は実行時に atcoder.jp から取ってきて手元に置くだけ。

  [レッドコーダーが教える、競プロ・AtCoder上達のガイドライン【中級編】](https://qiita.com/e869120/items/eb50fdaece12be418faa)

- **`contests/` 以下の解答**は自分で書いたもの。AtCoder 利用規約でも
  ユーザーが作成したプログラムの権利はユーザーに帰属する。
